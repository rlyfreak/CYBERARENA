# WEB-01 — Закрытый архив

**Категория:** Web Security
**Стоимость:** 100 баллов
**Уязвимость:** IDOR / Broken Access Control
**Сложность:** Easy

## 1. Описание задания

Участник получает доступ к внутреннему архиву организации. В списке отображаются два общедоступных документа, однако один служебный документ скрыт от обычных пользователей.

Цель — исследовать механизм просмотра документов, найти ошибку разграничения доступа и получить флаг формата `CTF{...}`.

## 2. Предполагаемое решение

### Шаг 1. Открыть лабораторию

Перейти по адресу:

`http://localhost:8080/lab/`

В интерфейсе доступны документы №101 и №102.

### Шаг 2. Изучить публичные документы

Открыть документ №102 «Журнал изменений».

В нём содержится информация о переносе документа №103 в закрытый раздел.

### Шаг 3. Изучить URL

При открытии документа браузер использует адрес:

`/lab/document?id=102`

Параметр `id` определяет, какой документ возвращает сервер.

### Шаг 4. Изменить идентификатор

Заменить `102` на `103`:

`http://localhost:8080/lab/document?id=103`

Сервер возвращает закрытый документ, несмотря на отсутствие прав администратора.

### Шаг 5. Получить флаг

В содержимом документа №103 отображается флаг из переменной окружения `WEB01_FLAG`.

Участник копирует его и отправляет через карточку WEB-01 на основной платформе CYBERARENA.

При первом правильном ответе начисляется 100 баллов.

## 3. Объяснение уязвимости

IDOR (Insecure Direct Object Reference) возникает, когда приложение позволяет обращаться к объектам по идентификаторам без достаточной проверки полномочий.

В учебной лаборатории закрытый документ скрывается из общего списка, но сервер не проверяет право пользователя на просмотр при прямом HTTP-запросе.

Таким образом, изменение параметра `id` позволяет получить защищённый ресурс.

**Класс уязвимости:** CWE-639 — Authorization Bypass Through User-Controlled Key.

## 4. Как исправить уязвимость в реальном приложении

Сервер должен проверять полномочия пользователя при каждом обращении к документу независимо от того, отображается ли документ в общем списке.

Для закрытых документов следует возвращать HTTP 403 или HTTP 404 пользователям без соответствующих прав.

Проверка доступа должна выполняться на сервере, а не только в интерфейсе.

## 5. Проверка лаборатории

Автоматические тесты исходного сервиса (после установки зависимостей из
`backend/requirements-dev.txt`):

`python -m pytest backend/tests/test_web01_lab.py -v`

Ожидаемый результат: 7 пройденных тестов.

На новом стенде сначала проверьте `docker compose ps --all` и доступность
`http://localhost:8080/lab/`. Войдите как администратор, создайте черновики
через `/admin`, укажите для WEB-01 ресурс `/lab/`, стоимость 100 и **точно**
тот флаг, который задан как `WEB01_FLAG` в локальном `.env`. Опубликуйте
карточку. Пробный участник должен увидеть документы №101 и №102, открыть
№103 прямым запросом, отправить флаг и получить 100 баллов только один раз.

Проверка изоляции Docker для отдельного тестового стенда:

`python scripts/ctf_isolation.py`

Этот скрипт ожидает запущенный стенд `cyberarena-ctf-check`, описанный в
[проверках CTF Core](ctf-verification.md), а не обычный стенд на порту 8080.
Зелёный локальный тест не подтверждает работу ноутбука Алины.

## 6. Примечания преподавателю

- Лаборатория предназначена только для локального учебного использования.
- IDOR является преднамеренной уязвимостью.
- Флаг задаётся через `WEB01_FLAG` и не должен храниться в исходном коде.
- Тот же флаг необходимо настроить в карточке WEB-01 на платформе.
- Не публиковать действующий флаг в студенческом условии или открытых материалах.
