# WEB-02 — публикация «Архива допуска»

Материалы находятся в `files/web-02/`: `index.html`, `script.js`, `style.css`.
Публичная ссылка карточки — `/files/web-02/`. Авторский
[write-up](WEB-02-writeup.md) хранится вне `files/` и должен отдавать 404 через
`/files/`.

Карточка: код WEB-02, название «Архив допуска», категория Web, сложность easy,
150 баллов. Условие: «Изучите клиентскую проверку роли через DevTools, откройте
журнал и восстановите токен из XOR-пакетов».

## Публикация на уже работающем стенде

После согласованного обновления приложения и материалов проверьте точные байты
`/files/web-02/`, `/files/web-02/script.js`, `/files/web-02/style.css`, наличие
CSP `sandbox allow-scripts` и недоступность write-up. В отдельном тестовом
стенде выполните `python scripts/check_web_02_flow.py prepare`, перезапустите
только тестовый `app` и выполните `python scripts/check_web_02_flow.py verify`.
Скрипт ограничен тестовым портом 18080 и тестовой учётной записью.

На рабочем стенде команда `seed-case` идемпотентно создаёт неопубликованный
черновик WEB-02, если его нет. Администратор затем должен открыть его в
`/admin`, установить поля выше и **ввести восстановленный по write-up флаг
через скрытое поле**. Публикуйте карточку только после проверки реального
материала и полного пути решения. Если WEB-02 уже настроен, не заменяйте его
флаг без отдельной проверки существующих решений и согласования.

После публикации участник должен открыть ссылку из карточки в Chromium,
получить отказ для `analyst`, через DevTools установить другую роль, увидеть
пакеты, восстановить токен, отправить неверный и верный ответы. Проверьте
однократное начисление 150 баллов, рейтинг и сохранность после перезапуска.

Статический JavaScript и все пакеты публичны по природе задания. Их нельзя
использовать для настоящей проверки прав или хранения секретов платформы.
