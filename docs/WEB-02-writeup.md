# WEB-02 — Архив допуска (закрытый write-up)

Этот файл хранится вне `files/` и не должен подключаться к публичному nginx.
Используйте его только для настройки карточки и проверки задания организатором.

На новом стенде сначала проверьте `http://localhost:8080/files/web-02/`,
затем создайте черновики через `/admin`. Для WEB-02 установите ресурс
`/files/web-02/`, сложность `easy`, стоимость 150 и восстановленный ниже
флаг в закрытом поле. Опубликуйте карточку после проверки материала.

1. Откройте `/files/web-02/` в Chromium. Роль `analyst` получает отказ.
2. В DevTools откройте `script.js`. Условие `allowedRoles.indexOf(role)`
   использует целое число как boolean. Для первого элемента массива результат
   `0` (ложь), для отсутствующей роли `-1` (истина). Это ошибка допуска.
3. Через консоль выполните
   `document.querySelector('#badge').value = 'visitor'`, затем нажмите кнопку.
   Станут видны три пакета, перечисленные не по порядку.
4. Отсортируйте пакеты по `seq`, соедините байты. XOR каждого байта с
   циклической маской `21 32 43 54 65 76 17` (hex), начиная с первого байта
   пакета `seq=0`, восстановит ASCII токен формата `CTF{...}`.
5. Отправьте токен на карточке WEB-02. За верное решение начисляется 150 баллов
   один раз; неверный и повторный ответ баллов не дают.

Данные и ошибка проверки находятся в публичном клиентском коде по замыслу.
Это учебная задача, а не модель защищённого хранения секрета на клиенте.
После отправки проверьте рейтинг и сохранность решения после
`docker compose restart`. Повторная отправка должна оставить баллы прежними.
Сверьте готовую карточку с [инструкцией публикации](WEB-02-publish.md).
Не помещайте этот write-up в `files/` и не передавайте его участникам.
