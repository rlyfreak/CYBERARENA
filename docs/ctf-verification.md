## Argon2: измерение под ограничениями

Сценарий `backend/tests/benchmark_ctf.py` запускает ASGI API приложения внутри
изолированного контейнера, с отдельной временной SQLite и настоящими серверными
сессиями. Это не измерение внешнего сетевого трафика через nginx и не тест
параллельной регистрации/входа.

- Лимит контейнера: 512 MiB, 1 CPU.
- 32 клиента, до 16 одновременных запросов; проверяются неверные флаги,
  поэтому каждый принятый запрос действительно выполняет Argon2.
- Завершено 32 из 32 проверок за 3.887 с.
- Максимальное время клиента с повторами: 3.879 с.
- Пик памяти cgroup: 138.08 MiB; OOM kill: 0.
- Одновременно выполнялись не более двух Argon2; 77 запросов получили
  временный отказ 503 и были повторены с короткими паузами для стресс-проверки.

Argon2id остаётся: измерения укладываются в лимит. На насыщении сервис применяет
отказ с Retry-After, а не неограниченную очередь. Реальным клиентам следует
соблюдать Retry-After (1 с). Числа зависят от CPU хоста и не являются SLA.
Ограничитель частоты и резервирование общей ёмкости выполняются до Argon2.
Лимит общедоступных Auth-операций в этот benchmark не входит.

## Почему изменена инфраструктура

В исходной схеме внешний nginx находился в обеих сетях. Из лаборатории запрос
`http://nginx/api/health` возвращал 200: это обходило прямую сетевую изоляцию.
Теперь внешний nginx находится только в app-net. Отдельный lab-gateway
связывает сети и проксирует только фиксированный lab-web:8000. В его конфигурации
нет приложения и нет управляемого клиентом upstream. Из лаборатории этот
gateway возвращает 404 на /api/health. Внешний nginx сохранил маршрут /lab/ и
обработку отказов. Дополнительный контейнер использует уже имеющийся nginx-образ
и ограничен 64 MiB. Исправление проверено в тестовом стеке; рабочая установка
автоматически не обновлялась.

## Повторение

Все команды ниже выполняются из корня отдельного worktree. Для Windows добавить
установленный каталог Docker resources/bin в PATH, если docker не найден.

```text
docker build -f backend/Dockerfile.test -t cyberarena-ctf-tests:local .
docker run --rm --memory 512m --cpus 1 cyberarena-ctf-tests:local python -m pytest backend/tests -q
docker run --rm cyberarena-ctf-tests:local python -m ruff check backend/app backend/tests
docker run --rm cyberarena-ctf-tests:local python -m pip check
docker run --rm --memory 512m --cpus 1 cyberarena-ctf-tests:local python backend/tests/benchmark_ctf.py
```

Для сквозных проверок задать **тестовые** CTF_CHECK_ADMIN_PASSWORD (12–128 символов)
и CTF_CHECK_SESSION_SECRET (не менее 32 символов) только в окружении процесса.
Не использовать рабочие секреты. На Linux вместо NUL использовать /dev/null.

```text
docker compose --env-file NUL -f compose.ctf-test.yaml -p cyberarena-ctf-check up -d --build --wait
python scripts/ctf_smoke.py prepare
python scripts/ctf_isolation.py
docker compose --env-file NUL -f compose.ctf-test.yaml -p cyberarena-ctf-check restart app
docker compose --env-file NUL -f compose.ctf-test.yaml -p cyberarena-ctf-check up -d --wait
python scripts/ctf_smoke.py verify
docker compose --env-file NUL -f compose.ctf-test.yaml -p cyberarena-ctf-check stop lab-web
python scripts/ctf_smoke.py lab-down
docker compose --env-file NUL -f compose.ctf-test.yaml -p cyberarena-ctf-check down
```

`prepare` удаляет только демонстрационные результаты тестового стенда.
Порт в скрипте жёстко ограничен 18080. Не менять его на рабочий порт.
`down` останавливает только тестовый проект и сохраняет его отдельный том.
Если повторно используется этот том, необходимо сохранить прежние тестовые
пароль/SESSION_SECRET или выделить новый проект и адаптировать скрипты.

В CI добавлен отдельный job с теми же Docker-, HTTP- и сетевыми проверками.
Удалённый CI ещё не запускался: ветка не отправлялась на GitHub.

## Оставшееся до демонстрации

Платформа и минимальное управление реализованы. WEB-01 пока является заглушкой,
а черновики WEB-02/CRYPTO-01 ещё требуют условий, материалов и флагов. Нужно
подготовить и независимо пройти три упражнения, затем проверить операции
администратора на демонстрационной копии базы. Расширение админ-панели
предусмотрено в `ctf-core.md`; CLI не является единственным интерфейсом.
