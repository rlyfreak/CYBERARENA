# CYBERARENA
Локальная CTF-платформа команды 404клуб для ИТ-спринта 2026 (Школа 21).
На чистом ноутбуке карточки заданий нужно настроить и опубликовать отдельно:
наличие файлов в Git само по себе не создаёт готовый турнир.

## Первый запуск

Нужны Git с доступом к этому репозиторию, Docker с Compose, работающий
Docker Engine и свободный порт 8080. Отдельный Python на Windows не нужен:
секреты создаются средствами PowerShell, а решение CRYPTO-01 приведено
на PowerShell и Python. На Windows запустите Docker Desktop; команды ниже
выполняются в PowerShell. Пока есть интернет, получите репозиторий и
перейдите в его корень:

```powershell
git clone https://github.com/rlyfreak/CYBERARENA.git
Set-Location CYBERARENA
docker compose version
docker info
```

Если `docker info` не отвечает, запустите Docker Desktop.

1. Скопируйте `.env.example` в `.env`:

   ```powershell
   Copy-Item .env.example .env
   ```

   Это действие нужно только при первом запуске: существующий `.env`
   не перезаписывайте.

2. Откройте `.env` в локальном редакторе и замените `ADMIN_PASSWORD` собственным
   паролем длиной **12–128 символов**. На Windows выполните `notepad .env`.
   `ADMIN_USERNAME=admin` можно оставить.
3. Сгенерируйте случайный `SESSION_SECRET` и вставьте его в `.env`:

   ```powershell
   $rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
   $bytes = New-Object byte[] 48
   try { $rng.GetBytes($bytes) } finally { $rng.Dispose() }
   [Convert]::ToBase64String($bytes)
   ```

   Скопируйте **только выведенную строку** после `SESSION_SECRET=`.
   Она содержит 64 символа; требуется минимум 32. Результат команды — секрет:
   не публикуйте его и не отправляйте в логи CI, отчёты или переписку.
4. Задайте в `.env` `WEB01_FLAG` в формате `CTF{...}` с собственным
   случайным токеном. Для генерации подойдёт:

   ```powershell
   $rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
   $bytes = New-Object byte[] 12
   try { $rng.GetBytes($bytes) } finally { $rng.Dispose() }
   'CTF{' + (($bytes | ForEach-Object { $_.ToString('x2') }) -join '') + '}'
   ```

   Скопируйте выведенный флаг после `WEB01_FLAG=` только в локальный `.env`.
   Не оставляйте пустое значение из шаблона: лаборатория откажется запускаться
   с пустым или несовместимым флагом.
5. Соберите и запустите платформу:

   ```text
   docker compose config --quiet
   docker compose up -d --build
   ```

6. Проверьте все контейнеры:

   ```text
   docker compose ps --all
   ```

   Дождитесь статуса `healthy` у `app`, `nginx`, `lab-gateway` и `lab-web`.
   Если контейнер завершился или нездоров, смотрите [диагностику](docs/infra.md).
7. Откройте [http://localhost:8080](http://localhost:8080).
   Войдите под `ADMIN_USERNAME` (по умолчанию `admin`) с паролем из `.env`.
   При первом входе администратора потребуется сменить начальный пароль.

**Значения `REPLACE_WITH_YOUR_PASSWORD` и `REPLACE_WITH_RANDOM_SECRET` —
публичные заглушки. Замените обе до запуска; они не подходят для рабочей установки.**
Настоящий `.env` игнорируется Git; `.env.example` остаётся отслеживаемым шаблоном.
Для существующей установки сохраняйте прежний `SESSION_SECRET` и `.env` при
обновлении: смена ключа подписи сделает текущие браузерные cookie недействительными.

**`docker compose down -v` удаляет том SQLite вместе с данными.** Для обычной
остановки используйте `docker compose down` без `-v`. Обновление приложения
не требует удаления тома или пересоздания базы.

## Настройка трёх заданий

В `/admin` нажмите «Добавить черновики заданий кейса». Откройте каждый
черновик, укажите условие, сложность, адрес ресурса и флаг, затем опубликуйте
после проверки. Повторное добавление черновиков не заменяет уже настроенные
карточки.

| Задание | Баллы | Ресурс | Флаг для закрытого поля карточки |
| --- | ---: | --- | --- |
| WEB-01 | 100 | `/lab/` | Точно тот же `WEB01_FLAG` из локального `.env` |
| WEB-02 | 150 | `/files/web-02/` | Восстановить по [авторскому решению](docs/WEB-02-writeup.md) |
| CRYPTO-01 | 150 | `/files/crypto-01/challenge.txt` | Восстановить по [авторскому решению](docs/CRYPTO-01-writeup.md) |

Поля карточек и порядок публикации описаны в инструкциях
[WEB-02](docs/WEB-02-publish.md) и [CRYPTO-01](docs/CRYPTO-01-publish.md).
Для WEB-02 и CRYPTO-01 флаги из материалов не зависят от `.env`.
Авторские решения в `docs/` предназначены организатору. Не передавайте
репозиторий участникам до окончания турнира; nginx раздаёт только `files/`.

## Пробный тест на ноутбуке Алины

1. По адресу стенда откройте `/lab/`, `/files/web-02/` и
   `/files/crypto-01/challenge.txt`. Все три ресурса должны открываться.
2. Зарегистрируйте пробного участника через `/register`. В каталоге должны
   быть видны три опубликованных задания с баллами 100, 150 и 150.
3. Для каждого задания отправьте неверный, затем правильный флаг.
   Баллы должны начислиться один раз, повторная отправка их не увеличивает.
   Проверьте рейтинг.
4. Выполните `docker compose restart`, дождитесь `healthy` и убедитесь, что
   участник, карточки и результаты сохранились.
5. Перед показом при необходимости сбросьте **только результаты** через
   `/admin`. Эта операция сохраняет аккаунты и задания.
6. Пока интернет доступен, завершите сборку. Затем отключите интернет на
   целевом ноутбуке и повторите запуск уже собранных образов:

   ```powershell
   docker compose down
   docker compose up -d --no-build
   docker compose ps --all
   ```

   Проверьте вход, три ресурса и отправку флага. Зелёный CI и проверка
   на другом компьютере этот сценарий не подтверждают.

По умолчанию адрес стенда — `http://localhost:8080`. Если для участников
включён LAN-режим ниже, используйте фактический IP ноутбука и проверьте
доступ с отдельных устройств в этой же сети. Без работающей локальной сети
режим с отдельными устройствами недоступен.

## Доступ из локальной сети (по желанию)

По умолчанию платформа слушает только `127.0.0.1:8080`: она открывается лишь на
самом ноутбуке. Чтобы проверить её с других устройств по Wi-Fi, укажите в `.env`
**явный локальный IP** ноутбука (свой адрес подставьте вместо примера):

```text
NGINX_BIND=192.168.1.100
```

Затем выполните `docker compose up -d` и откройте
`http://192.168.1.100:8080` с устройства в той же сети. Используйте фактический
IP ноутбука и на самом ноутбуке: после привязки к конкретному адресу
`localhost:8080` обычно недоступен. Чтобы вернуться к режиму по умолчанию,
удалите строку из `.env` и снова выполните `docker compose up -d`. Данные
SQLite находятся в томе и при этих командах сохраняются; не добавляйте `-v`
к `docker compose down`.

Не указывайте `0.0.0.0`: порт откроется на всех сетевых интерфейсах. Наружу
публикуется только nginx, у приложения, SQLite и `lab-web` портов нет. В этом
режиме порт 8080 доступен всем в сети. В Windows Firewall разрешите входящие
подключения к TCP 8080 только из доверенной
локальной подсети. Гостевая Wi-Fi сеть может запрещать связь между устройствами;
тогда выберите сеть без изоляции клиентов. Внешний интернет для турнира не нужен,
но работающая локальная сеть нужна. Если IP ноутбука изменился (другая сеть или
DHCP), обновите `NGINX_BIND` и снова выполните `docker compose up -d`; старый
адрес может помешать публикации порта. `docker compose config --quiet` проверяет
синтаксис, но не существование адреса на ноутбуке и не доступ с другого устройства.
HTTP в этой сети не шифрует пароли и сессии: используйте отдельную доверенную сеть
и временные турнирные учётные данные, не совпадающие с личными паролями.

## Приёмка по кейсу Школы 21

Цель MVP — локальный мини-турнир для 5–10 участников на одном ноутбуке без
интернета во время демонстрации. Критерии, репетиция офлайн, публикация трёх
заданий и протокол проверки описаны в [чек-листе приёмки](docs/school21-acceptance.md).
Публичный сайт и HTTPS не требуются для этой защиты.

Короткие команды эксплуатации: `docker compose logs --tail=100` — логи,
`docker compose down` — остановка с сохранением данных,
`bash scripts/backup-db.sh` — копия SQLite. Сброс только результатов выполняется
в `/admin`; `bash scripts/reset-data.sh` удаляет **все** демонстрационные данные,
включая пользователей и задания. Скрипты `.sh` запускаются из Bash (в том числе
WSL или Git Bash на Windows). Перед полным сбросом сохраните нужную копию.
